\section{Setup}
\label{sec:setup}

\subsection{Model and data}

All experiments use \texttt{Qwen/Qwen3-4B-Instruct-2507} \citep{qwen3report2025}, a 36-layer decoder-only transformer with a 2560-dimensional hidden state. The dataset consists of 444 LiveCodeBench \citep{jain2024livecodebench} tasks spanning the easy, medium, and hard difficulty tiers. Every experiment runs on a single NVIDIA DGX system.

\subsection{Hidden state capture}

Across all task attempts, the hidden state at the final prompt token is extracted from a prompt-only forward pass, before the autoregressive continuation begins. This yields a single 2560-dimensional vector per task per attempt at each captured layer. Hidden states are captured for the upper transformer blocks (layers 29--36), where linear decodability of high-level properties tends to concentrate in the probing literature \citep{alain2016probes}. The specific layer used for all subsequent analyses is selected by nested cross-validation (CV) in Section~\ref{sec:probe_results}.

\subsection{Repair-B policy}

For tasks where the model's first attempt fails the unit tests, an iterative repair procedure (``repair-B'') is invoked, with a maximum of 5 total attempts per task. Each attempt is a fresh forward pass on the full prompt, with no state carried over from previous attempts. The repair prompt for attempt $k+1$ is constructed as
$$\{\text{original problem}\} + \{\text{failure-type sentence}\} + \{\text{previous code}\} + \{\text{error output}\} + \{\text{fix instruction}\},$$
where \emph{previous code} is the model's own output from attempt $k$, \emph{error output} is the stderr captured by the verifier when attempting to execute that code against the unit tests (for syntax errors this is the parser's own diagnostic, since the code is rejected before any statement runs), and the \emph{failure-type sentence} is a single line of the form ``Your previous attempt produced a \texttt{\{failure\_type\}} error'', with \texttt{failure\_type} drawn from the failure taxonomy applied by the verifier: assertion, runtime, syntax, timeout, and a rare ``unknown'' fallback for failures that produce no stderr (out-of-memory, segfaults, etc.). Generation is capped at 768 new tokens per attempt. Two filters are then applied to the trajectories before the repair-direction analysis in Section~\ref{sec:repair_geometry}; see that section for the filters themselves and the resulting clean sample. The pre-generation probe in Section~\ref{sec:probe_results} uses all 444 tasks at attempt 0, with no filtering, because the two filters address a problem specific to the repair-direction analysis and do not apply to it.
